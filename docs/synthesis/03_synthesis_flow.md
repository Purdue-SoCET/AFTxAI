# 03 - Synthesis & Standard-Cell Technology Mapping

This document details the complete flow that transforms elaborated SystemVerilog RTL into a technology-mapped gate-level netlist targeting the **SkyWater SKY130 High-Density (`sky130hd`)** standard-cell library.

---

## 1. What is Standard-Cell Technology Mapping?

During RTL design, hardware is described using behavioral assignments (`if`, `case`, `+`, `*`).
1. **Generic Synthesis (`synth -top aft_synth_top -flatten`):** Translates behavioral code into generic Boolean logic equations, multiplexers (`$mux`), arithmetic units (`$add`), and abstract D-flip-flops (`$dff`).
2. **Sequential Mapping (`dfflibmap`):** Replaces abstract flip-flops with actual physical sequential cells from the PDK (e.g., `sky130_fd_sc_hd__dfxtp_1`).
3. **Combinational Mapping (`abc`):** Decomposes logic equations and multiplexers into an AIG (And-Inverter Graph) and maps them into physical NAND, NOR, Inverter, AOI, and OAI standard cells available in the target `.lib` file.

---

## 2. Complete Synthesis Script Workflow

The automated synthesis command sequence inside Yosys is executed as follows:

```tcl
# 1. SystemVerilog Elaboration with slang
read_slang --single-unit --top aft_synth_top -I ... [source files]

# 2. Hierarchy Check
hierarchy -check -top aft_synth_top

# 3. Generic Logic Synthesis and Flattening
synth -top aft_synth_top -flatten
stat -top aft_synth_top

# 4. Flip-Flop Mapping to SKY130HD Liberty
dfflibmap -liberty /OpenROAD-flow-scripts/flow/platforms/sky130hd/lib/sky130_fd_sc_hd__tt_025C_1v80.lib

# 5. Combinational Optimization & Technology Mapping via ABC
abc -liberty /OpenROAD-flow-scripts/flow/platforms/sky130hd/lib/sky130_fd_sc_hd__tt_025C_1v80.lib

# 6. Dead-Logic Removal
clean

# 7. Final Technology Mapping Report
stat -liberty /OpenROAD-flow-scripts/flow/platforms/sky130hd/lib/sky130_fd_sc_hd__tt_025C_1v80.lib

# 8. Netlist Generation
write_verilog -noattr /work/synth/out/netlist_synth.v
```

## 3. Measured Baseline Synthesis Results (Commit `0a1aa68`)

The full-chip synthesis baseline with the default register-based RAM (`ff_ram.sv`) produced the following measured results:

| Metric | Measured Baseline Result | Notes |
|---|---|---|
| **Generic Cells (pre-techmap)** | **406,397 cells** | In Yosys post-`synth -flatten` |
| **Generic Flip-Flops** | **159,878 DFFs** | Dominated by 131,072 RAM flops |
| **Mapped Standard Cells** | **233,481 cells** | SKY130HD physical gates |
| **Total Standard-Cell Area** | **5,799,221.91 µm² (~5.80 mm²)** | Standard cell footprint |
| **Sequential (Flop) Area** | **4,755,782.40 µm² (~4.76 mm²)** | **82.01% of total chip area!** |
| **Combinational Cell Area** | **1,043,439.51 µm² (~1.04 mm²)** | Logic, ALUs, buses, peripherals |
| **Mapped Netlist Size** | **~48 MB (`netlist_synth.v`)** | ASCII gate-level Verilog |

### Key Architectural Takeaway:
Over **82% of the standard-cell silicon area** in the baseline design was consumed exclusively by D-flip-flops used to implement on-chip RAM. An array of $4096 \times 32$ bits required **131,072 flip-flops**, each measuring $\approx 36.3\ \mu\text{m}^2$. This provided the primary motivation for the SRAM Macro Optimization project.

## 4. Netlist Cleanup for Downstream Timing Tools

Commercial and open-source signoff tools (OpenROAD, OpenSTA, Cadence Innovus) reject Verilog netlists containing:
1. Behavioral display statements (`$write`, `$display`).
2. SVA assertions or covergroups (`$check`).
3. Unresolved internal Yosys primitives (`\$_TBUF_`).

A clean netlist `netlist_sta.v` is generated by removing empty behavioral task blocks and linking structural macro cells.
